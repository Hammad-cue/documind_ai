## 3. Record field extraction (CUAD)

40 contracts (0 skipped), model `openai/gpt-oss-20b`, 38.6 s per contract. A prediction is correct when its quoted evidence overlaps the lawyers' span or its value matches (same date / parties / jurisdiction).

| Field | Precision | Recall | F1 |
|---|---:|---:|---:|
| parties | 100.0% | 100.0% | 100.0% |
| signed date | 88.0% | 59.5% | 71.0% |
| effective date | 77.1% | 84.4% | 80.6% |
| expiry date | 100.0% | 35.7% | 52.6% |
| auto renewal | 90.0% | 56.2% | 69.2% |
| notice period | 26.9% | 70.0% | 38.9% |
| governing law | 90.0% | 77.1% | 83.1% |
| **All fields (micro)** | **80.7%** | **71.7%** | **75.9%** |

**Evidence and review**

- Quotes found word-for-word on the cited page: **175/176** (99.4%) — the model almost never invents evidence, so every value can be checked against its page.
- Wrong predictions already sent to the human review queue: **2/34** (right ones sent: 7/142). Most errors carry a real quote that answers a slightly different question, so confidence and grounding alone do not catch them — a limitation and a direction for future work (e.g. a second model checking each value against its field definition).

**Reading these numbers**

- CUAD's labels differ from ours for two fields. *Notice Period To Terminate Renewal* covers only notice to stop a renewal, while our *notice period* is any termination notice — so many of our correct values count as false positives. *Expiration Date* is often a duration ("continues for five years"), while we extract an explicit date only when one is written, which lowers recall.
- Parties, signing date, effective date and governing law use the same definitions as CUAD and are the fairest measure.
